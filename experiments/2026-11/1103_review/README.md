## コード・設計上の注意点

### 良かった点

- `eval()` と `inference_mode()` を使用。生成サンプリングは行わず、同一入力をforwardする測定。
- 高速Tokenizerの文字offsetで、2つの`STATE:`の末尾トークンを特定。2位置のtoken IDも照合している。
- 因果マスクにより、手がかり前の位置は未来の手がかりを参照しない。元コードにHidden Stateの不変性チェックがあり、保存スコアの再検査でもpreは一定。
- Yを対象とするときProbeスコアを反転している。集計はcue・対象入替え・層を概念ペア内で平均した上で行う。
- Probe学習・説明文評価・本実験の文字列は分けている。標準化も学習データでfitしている。

### 解釈を制限する点

1. **Probe学習が少ない。** 896次元に対して16学習入力。名前2文型＋3説明×2文型を各クラスに使う。評価12入力も実質6説明文を2文型で言い換えたもので、12個の独立した意味的事例ではない。訓練・評価は別文字列でも、黄色い果物・鍵盤などの特徴が共通。高いAUCだけで任意の文脈への汎化は保証できない。
2. **v2とv3のProbe記述バンクが同じ。** 禁止対象の入替えは良い対照だが、Probeのバイアスに対する独立した再現ではない。
3. **v2の`unrelated`は実際には「距離が最も遠い四分位」。** 元の無関係Cueとは一致しない場合がある。数式の誤りではないが、真に無関係な基準として説明してはいけない。`v2_bin_label_audit.csv`で対応を保存した。
4. **距離・長さ・語彙・文章内容が同時に変わる。** 長さの回帰調整だけで交絡がすべて消えるわけではない。MiniLMで意図した方向に並ばないCueもある。失敗例だけを結果を見て黙って除かない。
5. **測定はユーザー入力内の2つのマーカー位置。** LLMが回答を生成した最中の思考過程、いったん忘れた後の再想起、経過時間そのものではない。
6. **二値ProbeはX対Yの軸。** 得点差が縮む原因は、対象情報の抑制、比較情報の変化、文脈全体の影響など複数ありうる。今回の差だけで対象固有の抑制機構と断定しない。
7. **層比較には注意。** 層ごとに別Probe・別学習スコアSDを使う。Transformersの最終hidden stateは最終正規化後で、直前層の未正規化出力と読み出しの段階も同一ではない。層間の数値差をそのまま絶対的な活性量の差とみなさない。
8. **再現性の情報が不足。** 元実験は入力CSVのcommitは固定しているが、モデル重み/tokenizerのrevisionや全依存バージョンは固定していない。Hidden StateとProbe本体も元実験では保存していない。保存スコアの再集計はできても、同一環境での完全再現までは保証できない。

20構成は、元の学習、説明文を各クラス1つずつ抜く9通り、同じ9通りで名前の学習例を除いたもの、説明文だけの全例学習。説明文の全フレームをまとめて除き、同じ説明のフレーム違いが残ることを防ぐ。ラベルを説明文単位でシャッフルする負の対照も、22/23/24層で各ペア10通り実行する。

モデルの現在のrevisionを実行開始時にSHAへ解決し、重みとTokenizerに同じSHAを指定。元実験の不明なSHAを遡って復元するものではない。FP32・eager attentionを使用し、元のFP16実行に対する数値条件の感度も含む。実測値は同じ新規実行内で比較する。

Hidden Stateを入力SHAごとのNPZに保存し、中断後は同じ環境なら再利用。環境が違うとキャッシュ再利用を拒否する。入力ハッシュ・ソースcommit・実行環境も保存し、完了した場合のみ`completed_manifest.json`を作る。指示のトークン長は実測して全件出力する。新しい手がかりはまだ人手評価・厳密な長さ合わせをしていないため、入力増加だけで「本実験が完成」とはしない。

この追加検証でも、マーカー以外の測定位置、独立した新概念群、人手で妥当性確認した距離、因果介入は未対応。次の本実験では、少なくとも新しい概念ペアと人手評価済みの手がかりを追加するのが望ましい。
