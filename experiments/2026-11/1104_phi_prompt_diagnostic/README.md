前回の72文をそのまま使い、各文に次の2種類の質問をする。計144入力。正答文も誤答文もすべて残すため、改善だけでなく悪化も確認できる。

| 条件 | 質問の方針 |
|---|---|
| A_original | 特定できなければnone（前回と同じ質問） |
| B_best_match | 最も合う名前を答え、カテゴリと無関係ならnone |

モデル・文・生成設定は同じ。毎回別会話として答えさせる。Phiを1回ロードし、FP16/SDPA・greedy・最大32tokenで実行。対象名は質問の選択肢として提示しない。これは既知の問題での探索的診断であり、新しい未使用問題での検証や本実験採用判定ではない。Bは質問とnoneの条件を合わせて変更しているため、一語だけの効果とはいわない。

内容と回答形式を分けて採点する。前回の原回答点検を踏まえ、grand piano/upright pianoは今回の両条件で同じくpianoとして採点する。前回の43/60や事前ゲートは変更しない。

独立した人の説明文評定は未実施。[空の評定用紙](blind_review.csv)はモデルの回答と意図した正解を載せず、第三者が名前・一意性・代替候補を記録するためのもの。空欄を評定済みとは扱わない。

## Colabでの実行

1. T4 GPUを選び、全セルを実行。
2. シークレット名は `GITHUB_TOKEN` が初期値。`GH_TOKEN` / `github_token` / `github_pat` も探す。別名ならセットアップセルの `SECRET_NAME` を既存のキー名へ変更する。秘密値そのものをコードやチャットに貼らない。
3. 最後のセルで結果をmainへ自動保存し、確認済みの結果リンクを表示。ZIPもダウンロードする。

シークレットへのノートブックアクセスが必要。リポジトリへの書込み権限がなければ、結果を残したまま停止して案内する。接続チェックは推論前に行うが、書込み権限そのものは最後の保存時に確認される。

## 保存されるもの

保存先：`ryouy/GraduationThesis` のmain、`1104_phi_prompt_diagnostic/results/<run_id>/`。

原回答、入力・出力token、実行環境・設定・SHA、条件別・概念別集計、同じ文の回答対比較、改善／悪化件数、グラフを1コミットで追加する。出力先以外のソースやREADMEはノートブックから変更しない。自動保存は採用判断を意味しない。原回答の点検は結果取得後に行う。

シークレットは認証ヘッダーにのみ使い、gitのURL・設定・環境変数・ノートブック・成果物へ書かない。アップロードは明示した結果ファイル12件だけ。実行前に採点を再検算し、結果SHAとGit blob SHAも照合する。mainの更新はforce=falseで並行更新を保護し、競合時は最新状態から最大3回再試行する。同一run_idの保存セル再実行では同一内容を確認して二重保存を避け、異なる内容は上書きしない。

失敗時は実験セルを再実行せず、**最後の保存セルだけ再実行**できる。ZIPも残す。通信・認証失敗のメッセージにはトークンやHTTP応答本文を含めない。
