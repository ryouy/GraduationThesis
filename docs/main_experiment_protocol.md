## 1. 研究の目的と研究質問

人間の思考抑制研究（「考えないで」という指示が逆に対象へ注意を向けることがあるという問題意識）を出発点として、LLMへの**抑制指示**と**対象概念Xへの意味的距離が異なる手がかり（Cue）**の組合せが、最終出力および内部表現に与える影響を調べる。人間と同じ心理過程がLLMに存在すると仮定するものではない。

- **RQ1（出力）**：CueとXの意味的距離に応じて、Avoid X条件におけるXへの言及はどのように変わるか。
- **RQ2（内部）**：同じ入力について、X/Yを識別する線形Probeのスコアと、Logit LensのX関連トークン予測は、指示条件・距離・層によってどのように変わるか。
- **RQ3（対応）**：出力にXが現れない場合でも、内部指標には条件差が残るか。指標同士はどの程度対応するか。

**期待する結果を前提としない。** 抑制、逆説的増加、無変化のいずれも結果として報告する。

### 3.1 パイロットで優先する概念

### 3.2 Yの扱い（必ず固定する）

- **Xごとに、既存結果で確認済みの1つのYをパイロット前に固定する**。目的はThink Y指示の代替対象と、X/Y Probeの比較軸を一定にすること。最終Yは距離監査・Probe監査後に `concept_pairs.csv` に保存する。
- 予備実験の比較相手は多くの組合せで識別性能が異なり、比較相手の変更が結果を変え得る。**本実験の結果を見てYを選び直さない**。
- X同士をYとして選ぶことは可能だが、XとYのCue関連性が極端に異なる組合せを避ける。XとYが両方Cueに出現しないようにする。
- 初回Probe検証で層24のAUCが高くても、その識別方向が抑制プロンプトに移った際に不変とは限らない。Probeを**推論過程の絶対的な「思考量」測定器と見なさない**。

## 4. Cue（手がかり）生成・意味的距離・選定

### 4.1 刺激設計

1. まずXごとに**英語の短い平叙文を50〜80文程度**、近い関連・間接的な関連・弱い関連・無関係の候補を幅広く作る。**現時点では候補文の生成と距離実測は未完了**。
2. Xの名称および表記揺れ、固定Yの名称をCueから除く。過度に定義そのものを答えてしまう文や、事実誤認・不自然な文、同内容の言い換えを監査する。
3. Xを表す**固定の短い英語定義文**と各Cueを `all-mpnet-base-v2` で埋め込む。主距離は `d_X=1-cos(emb(definition_X), emb(cue))`。補助値として単語 `X` とCueの距離、`d_Y`、`d_X-d_Y` を保存する。
4. まず距離のヒストグラムと分位点を確認する。0.3 / 0.6 / 0.9 を**無理な達成目標にはしない**。埋め込みコサイン距離は理論的には0〜2であり、特定の値を意味的な「近さ」の絶対尺度とみなせない。
5. **関連性が認められる範囲のCue**から、近・中・遠の各帯で**4文**ずつ選ぶ。帯の境界と選定コードは実際のCue距離分布に基づき固定し、各帯が十分離れるか監査する。距離帯内のCueの文長・情報量・具体性が極端に偏らないようにする。
6. **無関係Cue 4文/概念**は近・中・遠とは別のNegative Controlとする。これを「遠い」の集計に混ぜない。
7. Cue選定では**Avoid Xの応答やProbe結果を参照しない**。人手/独立評価による文の適切さの監査を記録し、採択後にCSVとSHA-256を凍結する。

**英語を使う理由**：過去のQwen Probe学習データが英語であり、埋め込みモデルも英語文評価に利用してきたため。日本語への一般化は別実験とする。

### 4.2 保存する刺激情報

`cue_id, target_x, comparator_y, cue_text, target_definition, semantic_distance_x, distance_x_label_only, semantic_distance_y, distance_diff_xy, distance_band, is_unrelated_control, token_count, word_count, provenance, semantic_relevance_review, ambiguity_flag, exclusion_reason, stimulus_version`

**交絡要因への注意**：Cueとの距離はX/Yの言い換えだけでは決まらない。文章の長さ・抽象度・頻度・語彙・カテゴリなどにも依存する。Cueの実測値は**観察的な刺激属性**であり、厳密に距離だけを独立に操作した因果実験とは断言しない。

## 5. 指示条件・質問文・推論設定

各 `X × Cue` に対して次の4条件を提示する。実際のモデル入力はQwenの**同一chat template**で構成し、指示の違い以外の説明・回答形式を統一する。

| 条件 | 英語の指示テンプレート（案） | 狙い |
|---|---|---|
| Base | `Read the clue and briefly name the thing it brings to mind.` | 指示なし基準 |
| Think X | `Think about {X}. Read the clue and briefly name the thing it brings to mind.` | Xへの注意誘導 |
| Avoid X | `Do not think about {X}. Read the clue and briefly name the thing it brings to mind.` | Xへの抑制指示 |
| Think Y | `Think about {Y} instead of {X}. Read the clue and briefly name the thing it brings to mind.` | 代替概念への誘導 |

全条件で後続入力を `Clue: {cue}\nAnswer with one short phrase.` とし、システムメッセージ、改行、句読点、回答フォーマットを事前に統一する。Avoid Xが「Xを出力してはいけない」という明示的な**出力禁止**を意味するかどうかは解釈に影響するため、ここでは心理学的モチベーションに近い `Do not think about` を採用し、別の禁止文は感度分析とする。

| 推論項目 | 採用案 | 理由 |
|---|---|---|
| `temperature` | 0.7 | 出力のばらつきを観察し、言及率を確率的に評価するため |
| `top_p` | 0.9 | 過度な低確率出力を抑えつつ変動を確保 |
| `max_new_tokens` | 128（上限） | 短い回答を求め、過度に長い文章を抑える。実際の生成長も記録 |
| 反復 | 各条件・Cueにつき5生成 | まず実行可能な規模でばらつきを把握する。推定誤差は大きく、本実験で増加を検討 |
| 乱数 | 固定した5つのseed、全条件で同じseed集合 | 再現性と条件間の比較可能性を高める。GPU/実装による非決定性は記録 |
| `do_sample` | `True` | 反復時に異なる応答を取得するため |
| 応答形式 | 短い英語の名詞句 | 明示的言及とAPI判定の解釈を単純化するため |

**パイロットでの動作確認が必要**：小型モデルが指示文を理解するか、空回答・形式逸脱・繰り返し・トークン切り詰めがどの程度あるかを最初に点検する。形式に失敗した回答も削除せず保存し、失敗率を報告する。

### 5.1 Cueなし対照

4条件それぞれでCueを与えない入力も用意し、指示文だけでのX側のスコア変化を確認する。**Cueなしは距離0・遠いCueではない**ので、距離回帰には含めず独立の対照として示す。

### 5.2 入力数と保存単位

| 区分 | 計算 | 数 |
|---|---|---:|
| 関連Cue | 4 X × 12 Cue × 4条件 | 192ユニーク入力 |
| 無関係Cue | 4 X × 4 Cue × 4条件 | 64ユニーク入力 |
| Cueなし | 4 X × 4条件 | 16ユニーク入力 |
| 合計 | | **272ユニーク入力** |
| 生成応答 | 272入力 × 5回 | **1,360応答** |

Hidden State（生成前）は原則272入力について1回ずつ取得し、応答の5反復と区別する。同一Cueの5生成を**5つの独立Cue**として扱わない。

## 6. 内部表現をどこで取得するか

- **主位置**：4条件すべてで、共通のCue入力直後・生成開始直前に相当する**最後の入力トークン位置（assistant生成開始位置）**。Qwenのchat template、assistant先頭トークンの有無を含めてノートブックで一致を検証する。
- **主層**：過去の汎化実験に合わせて**第24層**。同条件で第22・23層も取得し、比較可能性を維持する。
- **補助的な層別分析**：埋め込み出力を含む全Hidden Stateを保存または必要層に対して解析し、層1〜24の変遷を図示する。ただし、**第1〜21層のProbeは追加学習・独立評価が必要**。最終層のProbe係数をそのまま途中層へ当てない。
- **位置対照**：Cueなし入力の同位置。必要ならCue前/後の比較を追加するが、入力文面・トークン位置の違いによる交絡を明示する。
- モデル入力にXの名称が**Think X / Avoid X / Think Yの文面そのものとして含まれる**ため、内部スコアはXについての指示への反応も拾い得る。Avoid X − Baseだけで「純粋な抑制効果」とは判断しない。**Avoid X − Think X**はXの明示的提示を共有する比較として特に重要である。

## 7. 評価指標と採用理由

### 7.1 最終出力：主要な観察指標

| 指標 | 定義 | 採用理由 |
|---|---|---|
| **Explicit Mention Rate** | 生成文に事前固定辞書のX名称・同義語・語形変化が現れた割合 | 単純・再現可能でAPI判定への依存を避けられる |
| **Semantic Mention Rate** | 生成文が**Xそのものを指す・同定する**と独立のLLM判定器が判断した割合 | 名称を用いない言い換えを捉える |
| 形式逸脱率 | 空回答、文章過長、回答拒否、回答不能等の割合 | 小型モデルの指示追従性を把握する |
| 応答長 | トークン数 | 長さによる言及機会の差を監査する |

**Semantic Mentionの判定ルール案**：判定器に `target X` と `generated answer` **だけ**を渡し、生成条件・Cue・期待する方向は渡さない。応答がXを明確に指す場合のみ `yes`、曖昧なら `uncertain`、それ以外は `no`。**単なる関連語（例：ボートに対して「湖」）はyesにしない**。判定結果はJSON (`label, rationale_short, grader_model, grader_version`) で保存し、`uncertain` は人手レビューまたは独立集計とする。判定温度0。少なくとも層別/条件別に抽出したサンプルの人手監査を行い、一致率・不一致例を記録する。API利用不可でも明示的言及率は実行できる設計にする。

**注意**：出力の言及率低下は「回答にXが出にくくなった」ことを示すが、「内部でXを考えなくなった」証拠ではない。

### 7.2 線形Concept Probe：内部表現の主分析

**事前の品質確認**：X/Yの説明文から作った学習・評価データに対し、ROC-AUC、学習例の除外による頑健性、ラベルシャッフル・FDR補正の感度分析を行っていた。今後も、その評価データを抑制実験の「条件効果」推定と混同しない。

**本実験で見る値**：各入力の第24層Hidden State `h` に、当該X/Yに対して凍結したProbeを適用した**X側のdecision function（符号付き判別値）**。学習時にXを正例とする方向に揃える。

- **主比較**：同じ `X, Y, Cue, 層` について、`score(Avoid X) − score(Think X)` と `score(Avoid X) − score(Base)`。前者は少なくともXの明示提示を共有する。
- **統制**：`Think X − Base`、`Think Y − Think X`、Cueなし指示差。Yに対するCueの関連性も併せて確認する。
- **重要**：異なる概念ペア・層でdecision値の尺度が異なるため、生の値を横断平均しない。標準化する場合、**過去の学習データで推定した平均・標準偏差**など、結果を見ずに決めた基準を用いる。主解析はまず同一ペア内の条件差とし、標準化差は補助分析とする。
- **区別**：**ROC-AUCはProbe品質評価指標**、本実験の個々の入力で使う値は**decision score**であり、両者を混同しない。
- **限界**：X/Yの相対判別値はXの絶対的活性量を示さない。特にThink YはYの提示自体でスコアが動きやすい。抑制下の分布外入力での意味づけは探索的とする。

### 7.3 Logit Lens：補助的な層別分析

- 各層のHidden StateをQwenの**最終RMSNorm等の適切な正規化**と**出力head (`lm_head`)**に通し、その位置での「次トークン」予測logitsを計算する。
- **単一トークン名**なら、同じ境界・先頭スペースを揃えた対象トークンのlogitまたは全語彙softmax確率を追う。**候補のtokenizer分割を事前に記録**する。
- **複数トークンのX**では「最初のトークンの確率＝概念全体の確率」とみなさない。固定対象文字列の条件付き対数確率を、同じ接頭辞を用いた補助的なteacher-forcing計測として別に定義し、通常の単一位置Logit Lensと混ぜない。
- **出力**：層×条件×距離の曲線、各層でのX関連トークンの順位・相対logit差（比較候補Yの語彙特性にも注意）。最終層のLogit Lensが通常forwardの出力logitと一致するか**実装テスト**する。
- **限界**：Logit Lensは途中層の表現を最終語彙空間に無理に投影した可視化であり、途中層で実際に「Xを出力しようとした」「考えていた」という意味ではない。層方向の変化と生成時間方向の変化を混同しない。

## 8. 分析計画（結果を見る前に固定する）

### 8.1 主分析：言及率と指示×距離

- **解析単位**：生成応答ごとの0/1言及判定。ただし同一Cueの5回反復は依存しているため、Cue IDを持たせてクラスタ化する。
- **主要な説明変数**：指示条件（4水準）、Xへのコサイン距離（連続値）、**指示×距離の交互作用**。
- **主要な比較**：Avoid X vs Think X、およびAvoid X vs Base。距離が大きくなるにつれて言及率の差がどう動くかを推定する。
- **計画した集計**：概念別・Cue別の言及率、条件別平均、概念間変動、信頼区間。データが十分ならロジスティック混合効果モデル（概念・Cueの階層構造を考慮）。4概念パイロットでは一般化可能な概念間分散の推定が不安定なので、まず層別の効果量と可視化を重視する。
- **無関係Cue**：距離回帰から外し、Negative Controlとして別集計。
- **反復数の解釈**：1,360応答は1,360個の独立したCueではない。複数の概念・Cue間のばらつきと反復生成によるばらつきを分ける。

### 8.2 内部表現の分析

- 同一概念・CueについてProbeスコアの**対応のある条件差**を計算。主層24、補助層22/23、追加Probeの品質確認後に全層を分析。
- 指示×距離の変化と、Cueなし差を併記する。異なるX/YのProbeを無条件に平均せず、事前に固定した標準化か個別プロットを使う。
- Logit Lensは主に**説明的図示**とし、概念語のtokenization差・最終層一致テストを記録する。
- 出力の言及有無と内部スコアの関係を散布図・層別プロットで探索する。生成前Hidden Stateは同じ入力の5回生成で共通のため、反復5件を内部状態の5独立サンプルと扱わない。

### 8.3 結果章に用意する図

1. 刺激の距離ヒストグラム（採用Cueと除外Cueを表示）＋文長等の監査表。
2. 距離×指示条件によるExplicit/Semantic Mention Rateの曲線と不確実性。
3. 概念別の効果量（Avoid−Think X、Avoid−Base）を並べた図。
4. 主層でのProbe条件差×距離、代表的な概念の層別推移。
5. Logit Lensの層×条件曲線（対象名のtokenization監査を併記）。
6. **事前に定めた**典型例と、結果後に選んだ探索的な興味深い例をラベル分けしたケーススタディ。

## 9. 保存・再現性・監査

必須保存物：

- `config.json`：モデル名・revision、tokenizer、埋め込みモデルrevision、ライブラリ版、GPU、乱数、生成設定、パイロット/本実験の区別。
- `concept_pairs.csv`：X、凍結Y、辞書・概念定義、Probeの学習データIDと品質指標。
- `cue_candidates.csv` / `cue_selected.csv`：採用前の候補、距離、監査、除外理由、選定閾値。
- `stimulus_manifest.json`：刺激とプロンプトのSHA-256、選定コードcommit。
- `prompts.csv` / `generations.jsonl`：すべての入力、テンプレート、seed、応答、生成長、エラー。
- `output_judgments.csv`：明示的言及、API判定、保留、人手監査、判定モデル。
- `probe_scores.csv` / `logit_lens.csv`：位置・層・X/Y・スコア・モデルrevを含む。
- `analysis_summary.md`：主分析、補助分析、想定と異なる結果、脱落、限界、実行完了状態。
- 定期チェックポイント、SHA-256、完了マニフェスト。再実行では過去の結果を上書きせず、新しいrun IDを作る。

APIキー・PAT・Colab Secretはログ、notebook、GitHubへコミットしない。
