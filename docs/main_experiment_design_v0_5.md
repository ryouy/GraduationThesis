# ⑤ 本実験デザイン・解析仕様案 v0.7（50概念・6区分・Probe／Cue品質方針）

> 2026-11-24更新。**設計案であり確定プロトコルv1.0ではない。本実験は未実行。** 従来の20概念・5条件案を改訂。パイロットの刺激・結果は変更しない。今後の本実験では「Avoid X下でのCueの意味的距離と内部表現の関係」を中心に据える。

## 1. 研究目的と問い

「Xについて考えないで」と指示したLLMに、Xとの意味的距離が異なるCueを提示したとき、生成開始直前のHidden Stateと語彙空間への投影がどのように異なるかを調べる。**主たる説明変数はCue–Xの意味的距離**。指示条件の違い自体を主題としない。

- **RQ1（主）**：Avoid X条件において、Cue–Xの意味的距離と線形Concept ProbeのX/Y相対判別スコアにはどのような関係があるか。
- **RQ2（主）**：Avoid X条件において、その距離との関係はLogit Lensの層ごとのX/Y対数尤度マージンにどのように現れるか。ProbeとLogit Lensの傾向は一致するか。
- **RQ3（補助）**：距離との関係は、抑制指示を含まないNeutral X条件でも観察されるか。内部指標と最終出力へのX言及はどのように対応するか。

**解釈上の限界**：ProbeはX/Yの相対判別指標であり、絶対的な概念活性量や「考えている量」の直接測定ではない。Logit Lensは出力語彙への投影（複数トークンではteacher forcing）であり、内部で実際にその語を生成・思考した証明ではない。Cueの距離と意味内容・具体性は共変し得るため、距離だけの因果効果と断定しない。

## 2. 実験規模

- **目標50概念X**。カテゴリーの偏りを避けるため、暫定的に10カテゴリー×5概念を目指す。カテゴリー例：交通手段、動物、楽器、食べ物、家具、自然現象、道具、建築物、植物、衣服。**具体的なX、X/Yペア、カテゴリー配分は未凍結**。
- **6区分／概念**：意味的関連のあるCueを距離の近い順に5段階（Very Near / Near / Medium Near / Medium Far / Far）、これとは別にUnrelatedを1区分。**Unrelatedを連続距離の第6の点として回帰に入れない**。
- **各区分4 Cue**、計24 Cue／概念（関連20、無関係4）。Cueなし対照は別途1入力／概念・条件。
- **2条件**：Avoid X と Neutral Xのみ。Base、Think X、Think Y（Replace）は本実験には含めない。既存パイロットの結果は参照可能だが、本実験の条件間推定には混ぜない。
- **ユニーク入力（Cueあり）**：50×24×2＝**2,400入力**。
- **Cueなし対照**：50×2＝**100入力**。**合計2,500入力**。
- **Hidden State**：生成開始前の各入力1回（原則2,500件）。第22/23/24層Probeは最大**7,500行**（対象ペアすべてに採択済みProbeが存在する場合）。Logit Lens 24層×固定X/Y候補2つで**120,000行**。
- **出力の参考測定**：5 seed／入力とする場合は2,500×5＝**12,500回答**。ただし最終出力は補助指標であり、GPU資源の見積もり後に**1回または5回**を本実験前に固定してよい。生成反復を独立したHidden Stateの観測数として数えない。

### 指示文

既存パイロットと同じQwen chat templateと後続の入力形式を使用する。

- **Avoid X**: `Do not think about {X}. Read the clue and briefly name the thing it brings to mind.`
- **Neutral X**: `The word is {X}. Read the clue and briefly name the thing it brings to mind.`
- Cueあり: `Clue: {cue}\nAnswer with one short phrase.`
- Cueなし: `No clue is provided.\nAnswer with one short phrase.`

Neutral XはX名称の提示を共有する対照だが、文法・トークン数・単語位置は完全に一致しない。条件差を「純粋な禁止効果」とは解釈しない。

### 固定実行環境（暫定）

- モデル：`Qwen/Qwen2.5-0.5B-Instruct`、revision `7ae557604adf67be50417f59c2c2f167def9a775`。
- 意味的距離：`sentence-transformers/all-mpnet-base-v2`、revision `e8c3b32edf5434bc2275fc9bab85f82640a19130`。固定X定義文とCueのコサイン距離を計測し、実測連続値を保存。
- 出力を5回測定する場合の既存設定：seed `[101,211,307,401,503]`、temperature 0.7、top_p 0.9、max_new_tokens 128。モデルrevision・tokenizer・chat template・依存版・GPU・コードと刺激のSHAを記録。
- 一回のColabで全件を処理できる保証はない。**中断再開・チャンク単位保存**で条件を変更せず実行する。

## 3. 50概念とCueの事前採択

1. 意味領域の異なるXを候補として準備し、各Xに比較Yを1つ対応づける。Yの選択理由、語の曖昧さ、tokenizer分割、XとYの意味的関連を保存する。**Probeの条件効果を見てYを選び直さない**。
2. Probeについて、学習に含めない説明文でのX/Y識別性能（ROC-AUC等）とラベル置換・多重比較の感度評価を条件結果を見る前に実施。暫定的な参考基準はheld-out AUC≥0.80、各ラベル≥8評価文、ラベル置換FDR q<0.05。**これらはまだ正式採択基準ではなく、検証用文章・比較の集合・shuffle回数・閾値をv1.0で固定する**。50概念すべてのProbe採択は保証されない。
3. 採択基準を満たさないProbeペアはProbe主解析から除く。ただし該当XのLogit Lens・出力・距離解析を自動的に捨てない。50に足りないために基準を事後的に緩めない。50は**目標数**であり結果に合わせた選択を禁止する。
4. 各Xについて関連Cue候補を幅広く用意し、固定定義文との距離を実測。自然な関連性が保てる候補分布から近い順に**5つの帯**を構成し各4文採択する。無関係4文は内容として独立に確保する。各Xの距離帯の境界・実測値・重なりの有無を保存。**全概念で共通の絶対コサイン距離閾値を無理に適用しない**。
5. XとYの名称・事前固定同義語のCueへの露出、重複、不自然な表現、語数・具体性・文章タイプの偏りを点検。Stimulus version・採択理由・定義・SHAを固定。**内部指標・生成結果を見て刺激を差し替えない**。

## 4. 主解析（条件差を主目的にしない）

### 主解析①：Avoid Xにおける距離とProbeの関係

- 生成前の**最後の入力トークン位置**の第24層Hidden Stateに固定Probeを適用し、X側のdecision scoreを得る。
- **主関係**：各Xで、関連20 Cueの**連続実測距離 `distance_x`**とAvoid X条件のProbeスコアとの関連（傾き、分布、可視化）。概念ペア間で生のdecision値を平均しない。結果を見ずに定めた学習データ由来スケールで標準化するか、ペア内の傾きとして報告する。最終的な標準化規則はv1.0で固定。
- 第22・23層は感度分析。主層以外の検定を追加主張として大量に実施しない。

### 主解析②：Avoid Xにおける距離とLogit Lensの関係

- 全24層について固定したX/Y候補の対数尤度マージン `logP(X)−logP(Y)` を求める。複数トークンの候補にはteacher-forced sequence log probabilityを使うことを明示する。
- **主関係**：Avoid X条件での連続距離とマージンの関係。**第24層を主要な単一層の要約**とし、1–24層の距離別曲線は層別・探索的な可視化とする。native最終logitsとの一致・トークン化の監査を実施。
- X/Y候補長やYとの関連距離による影響を記録し、Probeと完全に同じ意味を測っているとは主張しない。

### 対照・補助解析

- **Neutral X**：同じX・CueのNeutral X条件でも距離との関係を推定。**距離×条件の交互作用（傾きの違い）**を、Avoid X固有の傾向かどうかを判断するための**副次解析**として扱う。Avoid−Neutralの平均スコア差自体は主目的ではない。
- **Unrelated／Cueなし**：連続距離回帰には入れず、別の対照として分布を表示する。
- **最終出力**：事前定義したXの明示的言及率を補助指標として集計。Semantic Mention RateはAPIによるstrict identificationの参考指標。生成した言及回数は内部状態の反復数ではない。

## 5. 統計・可視化

- 独立単位はCueであり、50概念の中にCueがネストしている。最終出力の反復を内部指標の独立観測に水増ししない。
- **主な効果の表現**：各概念で関連20 Cueの距離–内部指標関係（距離に対する傾き・散布図）を算出し、その傾きの分布をカテゴリー別にまとめる。概念間の非無作為選抜・カテゴリー内の共通性は限界として記述。
- 全体の不確実性には概念単位を尊重する階層的推定または**概念単位を再標本化するブートストラップ**などを検討し、単純に1,000 Cueを独立な概念とみなさない。主たる推定法・CI・ランダム効果・共変量は実行前にv1.0で一つに確定する。
- 5関連帯は**視覚化のための区分**。連続距離が主説明変数。無関係を第6の直線上の点に置かない。
- 補助的に文章長、具体性、X/Yへの相対距離、カテゴリー差を確認。ただしCue具体性と距離の交絡は観測的性質として残る。
- ProbeとLogit Lensは異なる主指標。方向が異なっても報告する。層×概念×距離帯すべての無補正有意差検定を行わない。正式な複数仮説の扱いはv1.0で固定。

## 6. 品質と停止規則

- モデル・Cue・X/Y・Probe学習・除外規則・コードを結果取得前に固定。保存チャンクの整合性、非有限スコア、プロンプト重複、final layer logits一致を検査。
- 失敗出力も保存し、観測後に都合の良いCueだけ削除しない。再実行は実装の整合性に関する失敗だけを理由とする。
- 50概念・5段階距離のCueを自然に準備できない場合、無理に距離を離さず不足・採択数を記録。**期待した有意差が出るまでCueや条件を改稿することはしない**。
- 独立した人手Cue監査・出力監査は従来のパイロットでは未実施。実施の有無を区別し、必要な最小範囲を指導教員と決める。

## 8. Probe品質・Cue構成の実施方針（2026-11-24追記）

### 8.1 Probeの独立検証

- 50個の対象概念Xについて、比較概念Yを1つずつ暫定設定し、既存のQwen実験と同様に線形Probeを学習する。**X/Yの名称や明白な別名を手掛かりとして学習させない**よう、学習・評価文から名称を原則除去し、名前を伏せても自然な記述になるか点検する。
- 学習用説明文と独立評価用説明文を別途作成する。単なる言い換えや同一事実の重複によるデータ漏洩を避け、対象ごとに内容の多様性を確保する。
- 未学習説明文でROC-AUCを評価する。**AUC 0.80以上を暫定的な採択目安**とし、既存のラベルシャッフル検査・多重比較感度も参考にする。ただしAUC閾値、評価文数、shuffle反復数、FDRの比較集合は**本実験の結果を見る前にv1.0で正式固定**する。
- 性能が不十分ならYの候補や学習文の不備を点検することはできるが、**条件別のHidden Stateや効果を一切見ない段階**に限る。再選択過程、候補数、不採用ペアを記録し、通過したペアだけ報告して選抜の事実を隠さない。
- Probeを採用できないペアはProbe主解析から外しても、対応するCue・Logit Lens・出力データを無条件に捨てない。50概念は目標であり、性能不足を理由に閾値を事後的に緩めない。
- 高AUCはX/Y説明文の識別能力であって、抑制下の「思考量」測定精度ではない。この区別を卒論で維持する。

### 8.2 Cueの文章タイプと距離帯を分離して設計

- 関連Cueの**5距離帯に各4文**を用意する際、近距離だけが部品・直接特徴、遠距離だけが一般的風景になる偏りを抑える。
- 文章タイプの暫定例は**動作・行為／場面・状況／道具・特徴／用途・社会的文脈**で、各距離帯に各タイプ1文程度を目安とする。カテゴリーによって適さないタイプは、**そのカテゴリー内で共通して使えるタイプへ事前に置き換え**、変更理由を記録する。タイプ構成を形式だけで無理に揃えない。
- 各概念に対して24文ちょうどではなく**多めの候補Cue**を作り、自然さ、対象X/Y・同義語の露出、重複、文長、具体性、文章タイプの分布を点検した後、固定定義文との実測コサイン距離に基づいて5つの関連帯を構成する。
- 距離帯は図示・均衡配置のための区分であり、**主解析では各Cueの連続実測距離を用いる**。意味的に無関係な4文は距離の第6段階として回帰に混ぜず、独立対照として扱う。
- 極端に不自然・不適切なCue、距離帯が十分に分離できない概念は、その理由を記録する。実際のQwenの生成・Probe・Logit Lens結果を見てCueを交換しない。

### 8.3 OpenAI APIの利用と検証の独立性

- OpenAI APIは**候補となるX/Y・説明文・Cueの生成、文章タイプ分類、自然さ・重複・名称露出の一次点検**に活用できる。大量の1,200採用Cueとその候補群の整備を効率化する。
- **同じAPIモデルによる「作成」と「妥当性評価」は独立した人手検証ではない**。独立評価用説明文は学習文と生成指示・内容を分け、重複監査と必要な抜き取り確認を行う。API判定を人間の正解ラベルと表記しない。
- 使用したモデル名、モデル版（取得できる範囲）、プロンプト、温度、生成日時、選定規則、結果ファイルを保存する。**APIキーはColab Secrets等で管理し、GitHubやノートブック本文へ記載しない**。
- 原則、自動スクリーニングで疑義のあるCueを優先点検する。無作為な抜き取りも併用して自動点検の見落としを確認する。全Cueの独立人手評定を実施しない場合は、その限界を明示する。

### 8.4 実施順序

1. 50概念Xと比較Y候補を広いカテゴリーから準備する。
2. 名前を伏せた説明文を用いてProbeを学習し、**未使用説明文で独立評価**する。採択過程を記録し、X/Yを固定する。
3. API等で各概念のCue候補を多めに用意し、文章タイプ・品質を点検する。
4. 実測距離に基づいて関連5帯×4文＋無関係4文を採択し、固定CSVとSHAを保存する。
5. 解析規則・モデル・コードを凍結した後、Avoid X中心の内部表現本実験を実行する。

**本節は実施方針の追記であり、本実験の実行・独立人手監査・50概念Probeの検証が済んだことを意味しない。**
