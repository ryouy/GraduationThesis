# 回答生成直前の内部表現：Concept Probe と Logit Lens

> 2026-11-24｜研究理解のための参考資料。実験の正式な仕様は[統合プロトコル v0.95](../main_experiment_protocol_v0_95.md)を優先する。ここでの模式例・数値は実測結果ではない。

[参考資料一覧](README.md) · [研究リポジトリTOP](../../README.md)

## 1. 最初に押さえること

今回の研究は、LLMに「Xについて考えないで」と指示し、Xとの意味的距離が異なるCue（手がかり）を与えたとき、**回答を生成する直前の内部表現がどう異なるか**を調べる。

- **Concept Probe**：内部表現から、Xと比較概念Yを区別する情報がどの程度読み出せるか。
- **Logit Lens**：各層の内部表現を語彙空間に投影したとき、XとYの候補文字列に対する予測傾向がどう異なるか。
- **最終出力**：実際にXが回答に言及されるか。内部指標との対応を見る補助資料。

ProbeとLogit Lensの出発点は同じ入力であるが、読み出す情報が異なる。

## 2. 入力トークンとは何か

LLMは入力文章をTokenizerで文字や単語の断片（トークン）に分割し、数値IDに変換して処理する。1単語が必ず1トークンになるとは限らない。

例：X = elephant、Y = lion。

```text
Do not think about elephant. Read the clue and briefly name the thing it brings to mind.
Clue: A large animal with a long trunk.
Answer with one short phrase.
```

この文章にQwenのチャットテンプレートが付加される。生成開始を示すassistantヘッダーも入力の一部である。

```text
[ユーザーの開始マーカー]
[抑制指示] [Cue] [回答形式の指示]
[ユーザーの終了マーカー]
[assistantの開始マーカー] [改行]
                                     ↑
                               最後の入力位置
                                     ↓
                             最初の回答トークン
```

上は模式図。正確なトークンIDと分割は固定Tokenizerで確認する。最後の位置は文章末尾のピリオドとは限らず、通常のQwenチャットテンプレートではassistantヘッダー後の改行になる。

## 3. 最後の入力トークンを観察する理由

Qwenのような自己回帰型Transformerでは、各トークンのHidden Stateが、それ以前の文脈を因果的Attentionによって参照できる。最後の入力位置の最終層の状態は、最初の回答トークンの予測に直接利用される。

したがって、ここでの測定は **指示とCueをすべて処理した後、自由生成を始める直前の文脈依存の表現** の観測である。改行そのものの意味を測るわけではない。

```text
 抑制指示         Cue        回答指示   assistantヘッダー
    │              │              │             │
    └──────────────┴──────────────┴─────────────┤
                                                ▼
                                      最後の入力位置
                                      Hidden State
                                                │
                                                ▼
                                     最初の回答トークン
```

この位置を採用する理由：

1. 指示・Cue・回答形式の情報をすべて参照できる位置である。
2. 回答によって入力文脈が変化する前の状態を条件間で比較できる。
3. 既存のProbeの学習・評価と同じ位置を使用できる。
4. 研究質問を「生成直前の表現と距離の関連」に限定することで、分析対象が明確になる。

ただし、入力全体のあらゆる概念情報が最後の位置に完全に残るとは限らない。

## 4. 層方向とトークン方向は別の軸

Qwen2.5-0.5B-Instructは24層、Hidden Stateの次元は896。各層には各入力位置に対応したベクトルがある。

```text
                     入力トークンの位置 →
               1       2      ...       N-1      N
  第24層       □       □      ...        □       ■  Probe + Lens
  第23層       □       □      ...        □       ■  Probe + Lens
  第22層       □       □      ...        □       ■  Probe + Lens
  第21層       □       □      ...        □       ◆  Lens
    …          …       …      ...        …       ◆  Lens
  第 1層       □       □      ...        □       ◆  Lens

  □ 今回の主解析では使用しない位置
  ■ ProbeとLogit Lensの出発点
  ◆ Logit Lensの出発点
```

- **トークン方向**：入力された情報の範囲に対応する。生成中のトークンを含める場合は回答の進行にも対応する。
- **層方向**：同じ位置の表現が浅い層から深い層へ処理される過程（layer-wise dynamics）。

現在は最後の入力位置に固定する。層別分析は時間的な思考の軌跡を観測することとは異なる。なお、Logit Lensで複数トークン候補を評価するときは、下記のように候補の接頭辞を追加する。

## 5. Concept Probe：概念の相対的な識別情報

### 学習と適用

1. XとYを記述する、名称を伏せた説明文を別途用意する。
2. 固定Qwenで各説明文の最後の入力位置のHidden Stateを取得する。
3. 各対象層についてStandardScalerと線形ロジスティック回帰分類器を学習する。
4. 学習に使っていない説明文で識別性能（ROC-AUCなど）を検証する。
5. 学習済みの係数を固定し、抑制実験の入力に適用する。

Pre-mainの実装に対応する抜粋：

```python
h = fwd.hidden_states[layer][0, -1, :]
score = clf.decision_function(
    scaler.transform(h.float().cpu().numpy()[None, :])
)[0]
```

scoreは同一X/Y・同一層での符号付き判別値である。高いほど、学習済み分類器のX側の方向に位置する（Xを正例とした場合）。ROC-AUCは分類器の独立評価性能であり、各入力のscoreとは異なる。

### 何が分かるか

例：同じAvoid X指示の下で、近いCueと遠いCueを与える。

| 項目 | 近いCue | 遠いCue |
|---|---|---|
| 内容例 | 長い鼻を持つ大型の動物 | 野生動物の保護活動 |
| Probeスコア（仮想） | +2.4 | +0.3 |

この場合、「近いCueの方が、生成直前の表現からXをYと区別する方向の情報が強く読み出された」と解釈する。ただし距離区分も例示で、実験では埋め込み距離を測定して決める。

**思考量、Xの絶対的な活性量、抑制成功率を直接測定しているわけではない。** Y側の情報や訓練と本実験の分布の違いもスコアに影響し得る。異なるペアや層の生スコアをそのまま比較・平均しない。

## 6. Logit Lens：層ごとの語彙予測傾向

Logit Lensは学習済みQwenの出力ヘッド（lm_head）を使って、各層のHidden Stateを語彙空間に投影する手法である。別途分類器を学習する必要はない。

現在の実装では、第1〜23層のHidden Stateに最終正規化を適用してからlm_headに渡す。第24層は取得済みの正規化後の表現を使う。最終層のlogitsがモデル本来のlogitsと一致することも確認する。

各層 l の主指標：

```text
margin_l = logP_l(X) - logP_l(Y)
```

値が高いほど、固定候補XがYに対して相対的に予測されやすい。中間層の投影値は通常の自由生成確率そのものではない。

### 複数トークンの場合（重要）

XやYが複数トークンの場合、Pre-mainでは候補文字列の先行トークンを強制入力するteacher forcingを使用している。

```text
元の入力 P
  P          → 候補第1トークンの logP
  P + t1     → 候補第2トークンの logP
  P + t1+t2  → 候補第3トークンの logP
```

各候補について各層の条件付き対数確率を合計し、XとYの差を取る。第1トークンは回答生成直前の位置から読み出すが、第2トークン以降は候補を追加した位置から読み出す。

したがって、**Probeは厳密に元の入力の最後の位置のみを測るが、複数トークン版Logit Lensは単一位置のHidden Stateだけを測るわけではない。** 候補長・トークン化・表記による偏りを記録し、自由生成中のダイナミクスとは区別する。

## 7. 二つの手法の比較

| 項目 | Concept Probe | Logit Lens |
|---|---|---|
| 読み出す情報 | X/Yの相対判別情報 | X/Y候補の相対的な語彙予測 |
| 方法 | 学習済み線形分類器 | Qwenの正規化・出力ヘッド |
| 別途学習 | 必要 | 不要 |
| 現行の測定層 | 22・23・24（主は24） | 全24層（主な要約は24） |
| 入力位置 | 元の入力の最後のみ | 最後から開始。複数トークン候補ではteacher forcingを使用 |
| 研究での役割 | 距離と概念識別情報の関連 | 距離と語彙投影・層別傾向の関連 |

異なる測定なので、両者が一致しないことも結果として報告する。片方がもう一方の妥当性を自動的に証明するものではない。

## 8. この実験で何を観察できるのか

例えば次のような仮想結果を考える。

| 観察項目 | 近いCue | 遠いCue |
|---|---|---|
| ProbeのX側判別値 | 高い | 低い |
| Logit LensのX/Yマージン | 高い | 低い |
| 最終回答にXが明示されるか | いいえ | いいえ |

出力上はどちらもXに言及していないが、内部指標は異なる。このような**内部表現と出力の対応・乖離**を検討できる。言及しなかったことだけで抑制成功を証明したり、内部指標が高いことを「無意識に考えていた」と断定したりはしない。

主分析はAvoid Xにおける連続距離との関係。Neutral Xでも同じCueを与えて距離傾向を比較する。両条件で同様の傾向なら、抑制固有の関係とは限らない。Neutral XはXの名称提示を揃えるが、文法・トークン位置まで一致するわけではない。

| 観察できること | 現行設計では直接観察できないこと |
|---|---|
| 生成直前のX/Y識別情報 | モデルが実際にどれだけXを考えたか |
| 距離と内部指標の関連 | 入力の途中でXが一時的に強まったか |
| 層による語彙投影の違い | 自由生成中にXが再浮上したか |
| Neutral Xとの距離傾向の違い | 距離だけの因果効果・抑制機構の全容 |
| 内部指標と出力の対応・乖離 | 内部指標が出力を因果的に決定したか |

## 9. 本実験に向けた方針

今回の問いには、**入力位置を最後に固定する設計が適している**。入力途中や自由生成中の状態まで主分析に含める必要はない。

中間層のProbeを将来追加する場合、各層専用の分類器を学習・独立評価し、層別AUCと比較可能な指標を検討する。全24層のProbeは検討案であり、現在の第22・23・24層の測定を変更した決定ではない。Logit Lensの全24層分析は現行仕様に含まれている。
